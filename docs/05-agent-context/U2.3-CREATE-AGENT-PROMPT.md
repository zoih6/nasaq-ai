# قالب طلب تشغيل وكيل U2.3 Create

انسخ النص التالي إلى الوكيل كما هو، ثم عدّل فقط ما بين الأقواس إذا احتجت:

```text
أنت وكيل تنفيذ داخل مستودع نَسَق:
https://github.com/zoih6/nasaq-ai

نفّذ مهمة U2.3 Create فقط، وفق Context Packet الإلزامي:
https://github.com/zoih6/nasaq-ai/blob/main/docs/05-agent-context/U2.3-CREATE-CONTEXT-PACKET.md

## الهدف
ابنِ شريحة Create Frontend-first vertical slice بثلاث compositions متخصصة:
1) document
2) deck
3) visual concept

يجب أن ينتقل المستخدم من Guided/Fast brief إلى structure ثم variants ثم edit ثم review ثم version ثم complete، مع dirty/save/storage failure/restore/version states وإيصال SimulationReceipt صريح.

## قبل أي تعديل
نفّذ بالترتيب:
1. افحص `git status --short --branch` و`git rev-parse HEAD` و`git rev-parse origin/main`.
2. افحص `bash tools/workspace-hygiene.sh status`.
3. اقرأ `AGENTS.md`.
4. اقرأ `docs/05-agent-context/README.md`.
5. اقرأ `docs/05-agent-context/CURRENT-STATE.md` و`HANDOFF.md`.
6. اقرأ Context Packet كاملًا:
   `docs/05-agent-context/U2.3-CREATE-CONTEXT-PACKET.md`
7. اقرأ فقط أقسام Create المطلوبة من `docs/01-product/U2-SERVICE-DEPTH.md` ومصفوفة U2 المذكورة في الـPacket.
8. افحص Learn وResearch وService Workbench كأنماط إعادة استخدام محدودة.

بعد الفحص، اكتب في رد قصير:
- base commit
- الملفات التي ستعدلها
- تصميم مختصر للحالة والعقود والـfixtures
- الاختبارات التي ستنشئها أو تشغلها
- أي خطر أو تعارض يحتاج توقفًا
ولا تبدأ تعديلًا خارج الـallowlist.

## الحدود الملزمة
- Frontend-only deterministic simulation.
- لا Backend، API handlers، database، queue، provider، LLM، live search، image generation، real file upload، export، n8n، Windmill، MCP، أو Manus API.
- لا تستخدم `eval` أو arbitrary HTML/URL/code execution.
- لا تضف dependency.
- لا تعدّل `package.json` أو `package-lock.json` أو `.env*`.
- لا تعدّل U2.1/U2.2 أو العقود الخاصة بـProduct Agent Runtime.
- لا تنشئ giant conditional component؛ استخدم Create composition مستقلة فوق Workbench المشترك.
- لا تعرض fixture أو demo asset على أنه توليد حي.
- لا تكتب `PASS` عند وجود flaky أو UNVERIFIED أو manual gate مفتوح.
- لا تنفذ commit أو push أو deploy.

## نطاق الملفات
التزم حرفيًا بـ`file_allowlist` في الـPacket. يمكنك إضافة ملفات Create الجديدة فقط داخل:
- `packages/contracts/src/services/create.ts`
- `packages/mock-api/src/services/create/`
- `packages/i18n/src/services/create-content.ts`
- `apps/web/features/create/`
- اختبارات `apps/web/tests/u2-create-*.test.ts`
- `apps/web/tests/e2e/service-create.spec.ts`
- evidence وملفات الحالة المسموحة عند التسليم فقط

إذا احتجت ملفًا خارج القائمة، توقف واشرح السبب وانتظر توجيهًا؛ لا توسع النطاق تلقائيًا.

## متطلبات السلوك
### Document
- title/outline/text blocks قابلة للتحرير.
- add/delete/reorder بأزرار ظاهرة، وليس drag-only.
- alternative واحدة على الأقل مع accept/reject.
- preview منفصل عن edit state.

### Deck
- 5 slides fixture على الأقل.
- title/body/notes edit.
- move up/down/duplicate/delete.
- منع حذف آخر slide.
- mobile يعرض slide واحدًا وقائمة خطية.

### Visual concept
- 4 demo variants محلية.
- اختيار ومقارنة مع وصف الفروق.
- ratio/palette/concept labels.
- caption وalt text قابلان للتحرير.
- alt مطلوب قبل ready.
- لا crop/render/export حقيقي.

### Versions and storage
- save بعد saved ينشئ ArtifactVersion جديدة.
- restore ينشئ نسخة جديدة ولا يمحو التاريخ.
- branch/duplicate يحتفظ بالعنوان وعلاقة parent.
- storage failure لا يدّعي saved ويعرض retry.
- receipt يوضح المحاكاة وعدم استخدام provider أو الشبكة.

## الاختبارات
ابدأ بالاختبارات المتأثرة فقط كما في الـPacket. لا تشغل full check أو full build أو cross-browser matrix قبل نجاح اختبارات Create الأساسية.

أنشئ مشغل Create E2E مستقلًا فقط إذا احتجته، وبنفس قواعد مشغل Research المحصّن:
- منفذ مخصص.
- `PLAYWRIGHT_BASE_URL` صريح.
- process group مملوك.
- `trap` cleanup.
- لا تستخدم broad `pkill`.
- لا تترك server/browser/artifacts.

## الأدلة والحالة
عند اكتمال الشريحة:
- أنشئ `docs/04-delivery/evidence/u2/u2-3-create/manifest.json`.
- اجعل evidence تغطي document/deck/visual، عربي/إنجليزي، mobile/desktop، version/error state.
- حدّث U2 traceability والحالة فقط بناءً على evidence حديثة.
- سجّل المخاطر والـmanual accessibility gates بصدق.
- لا تعلن U2.3 مغلقة بسبب نجاح آلي فقط إذا بقيت مراجعة بشرية أو flaky.

## التسليم
قبل التسليم:
1. راجع `git diff` و`git diff --check`.
2. تحقق أن كل ملف ضمن allowlist.
3. شغّل الاختبارات المحددة وسجل PASS/FAIL/FLAKY/UNVERIFIED.
4. نظّف workspace عبر `bash tools/workspace-hygiene.sh clean --all`.
5. لا تعمل commit ولا push.

أعد ملخصًا لا يتجاوز صفحة واحدة بهذا الشكل:

status: PASS | PARTIAL | FAIL | BLOCKED | UNVERIFIED
base_commit: <full sha>
final_commit: none
changed_files: [..]
implemented: [document/deck/visual/versioning]
tests:
  - command: <command>
    result: PASS | FAIL | FLAKY | NOT_RUN
    summary: <one line>
evidence: [paths]
open_gates: [..]
risks: [..]
next_action: <one sentence>
workspace: LIGHT | HEAVY
```

لا تلصق logs كاملة؛ اذكر عدد الاختبارات، أسماء الفاشلة، أول خطأ مهم، ومسارات الأدلة فقط.
```

## لا ترسل هذه الإضافات إلى الوكيل

- كامل سجل المحادثة.
- التقرير العربي الطويل.
- كل مجلد `docs/`.
- كل مستودعات n8n/Windmill/reference.
- صلاحية push أو deploy.
- طلبات أخرى مثل U2.4 أو Backend أو Product Agent Runtime.
